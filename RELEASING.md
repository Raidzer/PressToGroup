# Подготовка бета-релиза

Репозиторий: [Raidzer/PressToGroup](https://github.com/Raidzer/PressToGroup). Кандидат: `0.1.29-beta.1`, целевой клиент — WoW Retail 12.1.5, `Interface: 120105`.

## Проверки и пакет

Только для разработки нужны Lua 5.1 (`lua5.1` и `luac5.1`) и Python 3.10+. Для установки аддона они не нужны. Команды ниже выполняются из корня чистого checkout; если инструменты установлены под именами `lua`, `luac`, `python` или `py -3`, используйте их, предварительно проверив версии.

```sh
lua5.1 -v
luac5.1 -p Locale.lua Filters.lua Input.lua Engine.lua UI.lua WoW.lua tests/filters_test.lua tests/input_test.lua tests/engine_test.lua tests/ui_test.lua tests/wow_test.lua
lua5.1 tests/filters_test.lua
lua5.1 tests/input_test.lua
lua5.1 tests/engine_test.lua
lua5.1 tests/ui_test.lua
lua5.1 tests/wow_test.lua
python3 --version
python3 -m unittest discover -s tests -p package_test.py
python3 tools/package.py --output dist
```

`luac5.1 -p` проверяет синтаксис 11 Lua-файлов без создания байткода. Сборщик проверяет согласованность версий TOC и README, ссылки TOC и содержимое ZIP. Результат — `dist/PressToGroup-0.1.29-beta.1.zip` и `dist/PressToGroup-0.1.29-beta.1.zip.sha256`.

В архиве ровно 12 файлов под корнем `PressToGroup/`: шесть Lua-исходников, TOC, `Bindings.xml`, `Media/Icon.tga`, оба README и `LICENSE`. Тесты, инструменты, внутренние документы, Git и пользовательские настройки не поставляются. Фиксированные метаданные позволяют повторить ZIP в одной среде Python/zlib; одинаковые байты архива в разных версиях Python/zlib не гарантируются.

Один workflow GitHub Actions выполняет проверку Lua 5.1, пять Lua-наборов, тесты упаковки и сборку, затем сохраняет ZIP и SHA256 как artifact. Он не публикует GitHub Release.

## Минимальный клиентский прогон беты

Соло-поиск, подача и отмена заявки уже подтверждены пользователем в игре. Это не подтверждает все режимы ввода, бой, сохранение биндов после `/reload` и компанию. В следующих прогонах фиксируйте проверенный режим и контекст:

- Установить релизный ZIP; проверить загрузку без Lua-ошибок, версию в `/ptg log`, открытие окна, настройки и компактный вид.
- Соло проверить поиск, подачу и отмену отдельно через штатные способности, движение/прыжок, назначенную клавишу и «Следующий шаг»; одно нажатие должно выполнять не более одного доступного шага. Повторить доступные сценарии в бою и записать ограничения клиента.
- Проверить назначение клавиши и её сохранение после `/reload`, явный запуск помощника после перезагрузки, остановку при закрытии окна и сохранение отправленных заявок. Ручные заявки и заявки неизвестного происхождения после `/reload` не должны отменяться помощником.
- Компанией из 2–4 игроков проверить поиск лидером, общую заявку, подтверждение ролей на каждом клиенте, принятие приглашения через штатный диалог и остановку при смене состава, лидера или ролей.

Проблемы отправляйте в [GitHub Issues](https://github.com/Raidzer/PressToGroup/issues): версии WoW и аддона, режим ввода, соло/компания, бой, шаги воспроизведения, ожидаемый и фактический результат, относящийся к проблеме `/ptg log` или Lua-ошибка. Удалите имена игроков, переписку и другие личные данные.

## Публикация

Подготовка ограничивается локальными артефактами и [текстом релиза](RELEASE_NOTES.md); удалённые tag и Release на этом этапе не создаются. Для публикации выбрать конкретный проверенный commit, назначить ему tag `v0.1.29-beta.1`, приложить полученные из него ZIP и SHA256 и использовать подготовленный текст. В GitHub Release явно выставить `prerelease=true` (в интерфейсе — **Set as a pre-release**): суффикса `beta` в имени недостаточно. Не назначать тег непроверенному состоянию ветки.
